# Anonymous User Feedback

## Status

**No feedback has been collected yet** — this project has not had a live deployment tested by
real students as of this writing. This document exists to hold real responses once collected;
it currently contains only the collection template and privacy policy. Do not fill this
document with invented testimonials — an empty "Responses" section below is the honest state
until real sessions happen.

## Privacy policy for feedback collection

- No names, student IDs, emails, or other directly identifying information are collected.
- Device/browser type may be recorded only to help reproduce a reported bug, and is reported
  in general terms ("Android phone, Chrome") rather than anything more specific (not an exact
  device model or OS build number) unless the tester volunteers it to describe a bug.
- Feedback is collected via the template in `docs/TESTING_AND_QA.md` ("Anonymous student
  tester template"), either on paper, in a shared document, or through a simple anonymous form
  — not through any mechanism that logs IP address or ties responses to an account.
- Responses are summarized here in aggregate and by tester number only (Tester 1, Tester 2,
  …), never by name.

## How to use this document once real feedback exists

1. Recruit 3–5 students (the project's own target range) who were not involved in building
   the platform.
2. Have each complete the four tasks in the template in `docs/TESTING_AND_QA.md`.
3. Record each tester's raw responses under "Responses" below, verbatim or lightly cleaned up
   for readability — do not paraphrase away a specific complaint or specific praise.
4. Summarize patterns under "Themes" — but only after at least 3 testers have responded, so a
   single opinion isn't presented as a trend.
5. File any resulting bug or design issue in `docs/REVISION_LOG.md`, referencing which tester
   number(s) raised it.
