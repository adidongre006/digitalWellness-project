# Revision Log

was wrong, what changed, why, and whether the fix has been validated.

## How to add to this log

When you find and fix a real issue (not during initial construction, but afterward — a bug
report, a failed test, a security review finding), add a row here with an honest validation
status. Never mark something "Validated: passed" unless a test or manual check was actually
run and actually passed — see `docs/TESTING_AND_QA.md`'s honesty note, which applies equally
here.
